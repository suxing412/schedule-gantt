# 交给 WorkBuddy 的部署任务 · V2 / V3

请把本交付项目增量部署到现有应用 **https://schedule-gantt-37132.app.workbuddy.host/**，保留原域名、全部排期数据、`/p/<id>` 分享链接、四位编辑码和现有人工会话。这里是现有站升级，不是另建一个空站或迁移到其他数据库。

V2 的 AI 工具/独立密钥/协作者，以及 V3 的负责人和依赖高亮、连续缩放、任务条几何与 PNG 导出均已实现。请直接使用包内代码、官方 SDK 和 RPC，不重新设计权限、不改成前端校验编辑码，也不重新实现这些功能。

## 1. 升级前确认与恢复点

1. 阅读 `cloud/DEPLOYMENT.md`、`cloud/RPC.md`、`cloud/AI-TOOLS.md`、`cloud/VALIDATION.md`。本包独立运行的结果见根目录 `PACKAGE-VALIDATION.md`；本地验证不能代替真实托管网关验收，请按实际执行结果报告。
2. 确认正在操作上面域名对应的原应用、原数据库和现有管理员迁移角色。记录原部署版本、配置项名称及当前迁移状态，不输出配置密钥值。
3. 使用平台管理员备份/快照通道建立可恢复的升级前备份，覆盖 `schedule_private` 数据、函数定义和权限，并记录备份标识、时间与平台恢复入口。备份保留在平台受控存储，不能写入交付包。若平台没有可用恢复通道，先报告该限制；不要通过清表重建来“修复”。
4. 保留上一应用版本用于恢复。不要运行 `DROP SCHEMA`、`DROP TABLE`、`TRUNCATE`、重置全站数据或生成测试数据库的回归脚本来更新生产环境。

## 2. 按现状执行迁移

通过同一管理员迁移通道执行完整 SQL 文件，不逐段剪贴：

| 当前数据库状态 | 执行顺序 |
| --- | --- |
| 现有 V1（已具备 001 的五个 RPC） | `cloud/migrations/002_collab_external.sql` → `cloud/migrations/003_tool_actions.sql` |
| 真正全新环境 | `001_schedule_rpc.sql` → `002_collab_external.sql` → `003_tool_actions.sql` |
| 已有 V2 / 部分增量待补 | 先核实已提交结果；可按 `002` → `003` 重跑，不改变已有密钥和数据 |

**不要在 V2 数据库上单独重跑 001**，它会恢复旧函数并破坏新版必填字段写入。迁移文件分别包含事务边界；失败时确认该文件已回滚，停在失败点报告，不跳过检查或伪造成功。成功后按平台流程刷新 PostgREST schema 缓存，核实新增函数能被 SDK 调用。

旧排期升级后由人工编辑者用原四位码在 AI 接入面板生成首个可用 AI 密钥；不要批量重置用户密钥或替用户改编辑码。匿名无权直接读写底表、哈希、会话和预算；保持包内权限收紧逻辑。

## 3. 注入公开配置并启动单端口服务

解压后的独立交付目录为运行根目录，要求 Node.js 22+，启动命令 **`npm start`**（等价 `node cloud/serve.cjs`），默认端口 **3000**，平台可用 `PORT` 覆盖。页面已构建，运行时无需安装额外包或从 CDN 获取 SDK。

| 环境变量 | 配置 |
| --- | --- |
| `WORKBUDDY_ENDPOINT` | **必填**，当前应用 `publicConfig.endpoint` 的可信 HTTPS origin；不要留空，否则 HTTP AI 工具不可用 |
| `WORKBUDDY_PUBLISHABLE_KEY` | **必填**，当前应用 `publicConfig.publishableKey`，由平台运行时注入 |
| `NODE_ENV` | `production` |
| `PORT` | 平台分配端口；未设置时 3000 |
| `HOST` | 默认 `0.0.0.0` |
| `WORKBUDDY_FRAME_ANCESTORS` | 仅需跨源 iframe 预览时设置真实父页面 HTTPS origin，逗号分隔，不使用通配符 |

包内不附带真实公开配置值、四位码、AI 密钥或会话。不要要求用户提供数据库连接串、service-role 或 `SESSION_SECRET`；这个版本通过平台公开配置访问受控 RPC。平台需允许 Node Worker：`project.analyze` / `project.preview` 在受限 Worker 中计算。

路由必须保持：

- `/.cloud/**` → WorkBuddy 内置云网关。
- `/api/**`、`/llms.txt` → 本包 Node 服务，不能回退成首页 HTML。
- `/`、`/p/<id>`、静态资源、`/runtime-config.js`、`/livez`、`/healthz` → 本包 Node 服务。

MCP 适配器通过 `node cloud/ai/mcp.cjs` 在客户端本地走 **stdio**，不是网站的 `/mcp` HTTP 服务。远程 AI 可用 HTTP API：长密钥放在 external-session 请求的 JSON `apiKey` 字段；换得的会话 `token` 才放 `Authorization: Bearer <token>`。两者都不能放 URL。

## 4. 用独立临时排期做真实环境验收

保留用户现有排期不变；所有创建、错误码测试、密钥重置、并发操作、删除任务均针对新建的合成测试排期。可只读核对旧链接仍可打开，但不要对用户原排期做验证性写入。

1. 人工新建、一次性密钥展示、另一浏览器匿名查看、正确码编辑、刷新及换容器后数据保留；错误码拒绝，冲突保留草稿，退出后旧令牌拒写。
2. API：目录、OpenAPI、JSON 导出、正确/错误 AI 密钥、外部令牌动作、预览不写入、批量一步失败则全部不保存、同版本人机并发只一个成功。公开结果和错误中不泄露密钥/哈希/令牌；来源标记区分人工和外部。
3. 人工四位码重置测试排期的 AI 密钥后，旧密钥及旧 external 会话拒绝操作，原人工会话仍能使用。人工整份保存和外部动作接口不能混用会话来源。
4. 协作者列表必须有效会话才能访问；同名独立显示，无令牌字段；编辑态 20 秒心跳、隐藏/退出停止、60 秒后离线。人工与外部预算相互独立。
5. V3：`Alt + 滚轮` 连续放大/缩小，鼠标日期锚点稳定；切换日/周/月复位，`Shift + 滚轮` 横向滚动仍可用。月视图单日短条不越界，真实拖动和左右调整工期各一天与日期一致；撤销/重做正常。
6. V3：普通条/泳道条有间隙和圆角，汇总三角端无 15 px 偏移；节点符号保持日期居中。PNG 导出与当前缩放和间隙一致。负责人高亮与完整显式上下游依赖链可共存，切换高亮不改变云端版本。
7. 验证真实网关提交事务：错误码/超限响应后预算保留，并发请求不能越额度；拒绝 `Prefer: tx=rollback` 及响应转换等回滚路径。数据库 `RETURN` 无法阻止外层强制回滚，不能用本地 PG 测试代替此项。

`/healthz` 和工具目录成功只说明对应服务可访问，不等于数据库、授权、持久化或 UI 已通过。若平台不能保障事务提交或某项能力，请明确报告失败请求、错误和影响，不开放匿名写入来绕过问题。

## 5. 失败恢复与完成回报

- 迁移前失败：保持原部署和数据库，报告原因。
- 某份迁移失败：确认该事务回滚，保留之前已成功增量；修正平台权限/环境问题后按顺序重试，不用 001 覆盖 V2。
- 新应用部署失败：优先恢复上一应用版本，保留已提交的增量 schema，并用独立测试排期验证原有基础读写。不要删除新增列、函数或数据。
- 若必须恢复数据库快照：先暂停写入，记录升级后是否已有新数据，通过平台管理员恢复通道处理，避免覆盖升级后的有效修改；报告恢复点与影响，不自动执行破坏性 SQL。

部署结束请返回：实际网址、所执行迁移及结果、备份/恢复点标识、配置项名称（不含值）、上述验收逐项结果，以及所有未通过项和平台限制。只有真实执行通过才能写“通过”；不要只给健康检查截图或宣称本地测试等于生产验收。
