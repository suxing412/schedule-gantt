# WorkBuddy 云端部署说明 · V2 / V3

## 交付范围

交付内容包括前端 SDK 接入、业务 RPC 迁移、单端口 HTTP 服务、HTTP 工具接口、stdio MCP 适配器及测试。目标是增量升级现有网站 [schedule-gantt-37132.app.workbuddy.host](https://schedule-gantt-37132.app.workbuddy.host/)，保持原域名、排期数据、分享链接和四位编辑码。可直接发送给部署方的任务说明见 [HANDOFF-PROMPT.md](HANDOFF-PROMPT.md)。旧 Node 私有存储适配器不用于这一版本。

数据存 WorkBuddy 云端 PostgreSQL；HTTP 服务无业务数据文件、编辑会话内存或数据库私有凭据依赖，可在无状态容器运行。浏览器只得到平台公开的 `endpoint` 和 `publishableKey`。

旧本地版或 Node 版的数据不会自动上传。首次迁移请先导出排期 JSON，创建云端排期并设置新的四位编辑码，再通过页面导入；旧 scrypt 哈希不能直接转换为 bcrypt，不要复制旧哈希或私有数据库文件到云端表。

这段导入说明仅针对尚未上云的本地排期；本次已有云站升级直接保留原数据库，不应要求用户重新创建或导入现有云端排期。

## 0. 确认现有应用并建立恢复点

通过平台管理员通道确认原应用及数据库，记录当前应用发布版本、迁移状态和配置项名称，不记录密钥值。升级前使用平台备份/快照能力建立可恢复备份，覆盖 `schedule_private` 业务数据、函数定义和权限；记录备份标识、时间和恢复入口。备份留在平台受控存储，不能随交付包分发。若平台无可用备份恢复通道，先报告限制，不清表重建。

保留上一应用版本。迁移和验收不执行破坏性 SQL，不删除原排期、重置人工编辑码或批量轮换用户 AI 密钥；生产环境不运行会创建/删除随机数据库的测试脚本。平台验收创建独立合成排期，现有用户排期只作只读核对。

## 1. 执行数据库迁移

使用平台管理员迁移通道，按顺序执行：

1. `cloud/migrations/001_schedule_rpc.sql`：V1 基础表、校验器与人工编辑 RPC。
2. `cloud/migrations/002_collab_external.sql`：AI 独立密钥、会话来源、协作者和独立预算。
3. `cloud/migrations/003_tool_actions.sql`：数据库内细粒度动作和原子批量。

已有 V1 环境只执行第 2、3 份；新环境执行全部。完整重跑也必须保持 `001` → `002` → `003`，**不能在 V2 环境单独重跑 001**：它会恢复旧版函数，导致新版必填字段不再被写入。增量重跑 002、003 会保留排期、已有密钥与会话。使用同一个管理员角色；需要平台 `anon`、`authenticated` 角色和安装 `pgcrypto` 的权限，不要用 `anon` 迁移。V3 为前端更新，没有额外的 004 迁移。

每份 SQL 自带事务边界，须完整执行；某份失败时确认该事务已回滚，记录失败语句/错误并停止后续步骤。不要跳过权限检查或拆掉事务来强行继续。已经提交的 002/003 保留，排除原因后按上述顺序重跑。

旧排期升级后内容、链接、人工编辑码及会话保留。它们不会自动得到一个可见 AI 密钥；由有编辑码的人在 AI 接入面板生成/重置。新密钥仅返回一次，不可从数据库摘要恢复；重置同时撤销该排期全部 external 会话，保留 human 会话。

迁移面向该排期应用的独立数据库/环境。新安装的 `pgcrypto` 放入私有 schema；已有扩展保留原位置，但撤销其成员函数对 `PUBLIC`、`anon`、`authenticated` 的直接执行权，避免把原始加密函数暴露为匿名 RPC。其他既有显式授权保留，并授权当前迁移角色及已存在的 `service_role`。若其他应用或平台角色依赖 `PUBLIC` 间接获得这些函数权限，管理员必须先核实影响并为可信角色补充显式授权，不可直接在未经检查的共享数据库执行。迁移会检查撤权实际生效；失败时不能跳过检查继续上线。

不要将用户提供的演示用 `update_project` 或裸 `compareAndSwap` 开放给匿名用户。交付版更新接口会在数据库内部验证编辑令牌，再执行版本条件更新。不得向浏览器返回 `edit_code_hash`、会话令牌哈希或尝试额度表。

迁移完成后，按平台流程刷新 PostgREST schema 缓存；SQL 已包含 `NOTIFY`，但是否生效需在实际平台确认。数据库测试与平台验收说明见 `cloud/tests/README.md`，接口契约见 `cloud/RPC.md`。

**事务前提：** RPC 请求必须以提交事务执行，不能配置 `db-tx-end=rollback`，也不能允许调用方用事务偏好覆盖为回滚。错误编辑码和超限分支返回结构化业务错误并正常提交额度记录；不依靠会回滚计数的 SQL 异常。迁移会拒绝可识别的 `Prefer: tx=rollback`，但 SQL 无法阻止外层事务在平台侧强制回滚。部署方必须在真实网关验证这一点，不能只依赖本地 PostgreSQL 测试。

## 2. 注入公开配置

在托管服务环境变量中，将平台 `publicConfig` 映射为：

| 环境变量 | 值 |
| --- | --- |
| `WORKBUDDY_PUBLISHABLE_KEY` | 平台 `publicConfig.publishableKey`，形如 `wbpk_...`，必填 |
| `WORKBUDDY_ENDPOINT` | 平台 `publicConfig.endpoint`；**HTTP AI 接口必填**。仅浏览器 SDK 可在留空时使用当前网站 origin |
| `PORT` | 平台分配的单端口，默认 `3000` |
| `HOST` | 默认 `0.0.0.0` |
| `NODE_ENV` | 上线设置 `production` |
| `WORKBUDDY_FRAME_ANCESTORS` | 可选，平台需要 iframe 预览时填写逗号分隔的明确父页面 HTTPS origin；默认只允许同源 |

这是本项目提供的明确注入接口，不假设平台存在某个特定全局变量。静态服务通过 `/runtime-config.js` 生成 `window.SCHEDULE_RUNTIME`，再加载本地官方 SDK 和页面。环境变量由平台提供，不写进源码、提交记录、发布包或日志。`.env.example` 只是示例，服务不会自动加载 `.env`；需要本地文件时可用 Node 的 `--env-file` 参数，并将该文件留在交付包之外。

`publishableKey` 是浏览器公开配置，不是数据库密码。不要填入数据库连接串、service-role、TCB 或 COS 密钥。显式配置的线上端点必须为 HTTPS，并且不能带用户名、密码、查询参数或片段；HTTP 只允许开发模式的 localhost/127.0.0.1/::1。

若平台使用 Origin 校验，请允许真实发布网址；不要通过伪造 Origin 绕过限制。CSP 的 `connect-src` 仅包含同源和显式配置端点的 origin，不使用通配符。浏览器直接调用平台，必须让平台正确处理 Origin/CORS。HTTP 工具服务使用同一公开配置调用受控 RPC，没有私有数据库凭据或绕过授权的通道；须验证托管进程确实能调用配置端点。上游地址只取可信环境变量，不从请求 Host/转发头推导。

## 3. 启动 HTTP 服务

运行环境为 Node.js 22+。项目 `dependencies` 为空，SDK 的固定版本浏览器构建已随包提供，运行时不从 CDN 下载。

**解压后的独立交付目录**启动：

```sh
npm start
```

等价命令为 `node cloud/serve.cjs`，页面已构建。若直接在原始源码仓库开发，先执行 `node scripts/build-frontend.cjs`，再用 `node cloud/serve.cjs` 或 `npm run start:workbuddy`；原仓库根目录的 `npm start` 是旧 Node 服务，不要与独立交付包混淆。

默认访问 `http://localhost:3000/`。创建后分享链接形如 `/p/<32位小写hex排期ID>`，直接打开或刷新均可加载。托管入口指向此进程的单一 `PORT`；前端、runtime 配置和 HTTP 工具走同端口。

- `/livez`：进程活性，正常启动返回 HTTP 200。
- `/healthz`：配置和构建就绪情况；缺配置或缺构建文件返回 HTTP 503，齐全返回 200。**不代表数据库已经可访问或迁移已执行。**
- `/runtime-config.js`：浏览器公开配置，禁止缓存；不含服务器私有密钥。
- `/api/tools`、`/api/openapi.json`、`/llms.txt`：机器可读工具目录和说明，即使缺少云配置也可读取，不能替代云连通验收。
- `/api/projects/<id>`、`/api/projects/<id>/export`：公开排期和可导入 JSON。
- `/api/tools/call`：HTTP 工具调用；授权、版本、动作语义见 [AI-TOOLS.md](AI-TOOLS.md)。

配置缺失或 SDK 加载失败时必须显示配置/连接错误，不得回退旧 localStorage 样例。托管平台如果上线前先探活可用 `/livez`，发布完成后的 readiness 用 `/healthz`。

服务开放指定前端资源、健康检查和新工具路由，不通过 HTTP 提供 SQL、环境文件、测试、服务端源码或旧 Node API。云端 RPC 前缀 `/.cloud/` 须由平台保留；自建反向代理需把 `/api/`、`/llms.txt` 指向此 Node 服务，不能把它们回退成 SPA HTML。

托管环境须支持 Node `worker_threads`：公开分析与预览在受限 Worker 中执行，不能被平台禁用。MCP 客户端通过 `node cloud/ai/mcp.cjs` 启动本地 stdio 适配器，网站不提供 `/mcp` HTTP 端点。HTTP 外部密钥交换把长密钥放在 JSON 的 `apiKey` 字段，随后使用返回的短期 `token` 作为 Bearer；长密钥不直接当 Bearer，也不放 URL。

默认只允许同源嵌入；第三方平台确需 iframe 预览时，将实际父页面 origin 填入 `WORKBUDDY_FRAME_ANCESTORS`，例如 `https://preview.example.com,https://console.example.com`，不要照抄示例或猜测平台域名。不允许通配符、路径、用户名或密码；开发环境才允许 HTTP loopback。也可直接使用独立发布网址验收。工具服务不开放任意跨站浏览器写入；外部 AI 使用服务端 HTTP 或本地 MCP 客户端。

## 4. 平台验收

以下写入、错误凭据、密钥重置和并发测试全部使用新建的独立合成排期。不要对用户原排期做验证性编辑；只读核对其原链接、内容和版本即可。

1. 未注入配置时页面明确提示配置缺失；注入后刷新，新建排期、填写昵称及四位码，获得 `/p/...` 链接。
2. 第二个独立浏览器打开链接能看见数据，未输入编辑码不能修改；错误码不能获得会话。
3. 正确码取得编辑权限后修改任务、字段、依赖并刷新，数据仍在；另一浏览器可看到变化。
4. 同一个旧版本同时保存，两次更新只能成功一次；另一方保留草稿并提示冲突，不能静默覆盖。
5. 过期、伪造和其他排期的编辑令牌不能写入；直接查询私有表或调用私有函数不能取得哈希/令牌数据。
6. 错误码与超限返回后，尝试额度已提交；并发调用不能绕过额度。必须测试真实 PostgREST 的回滚偏好和事务配置，而非仅 SQL 成功路径。
7. 停止并重启静态服务或换容器后，排期仍可读取。健康检查不能替代这项持久化测试。
8. 新建排期返回一次性 AI 密钥；旧排期可用人工四位码生成密钥。普通公开读、导出及协作者列表不含密钥/令牌/摘要。
9. 错误 AI 密钥不能换令牌；正确密钥换得 external 会话。外部动作必须拒绝人工会话，人工整份保存必须拒绝外部会话；两种凭据预算互不挤占。
10. 从网站外部 GET 工具目录、公开项目和导出 JSON；用外部会话添加合成任务并读回。原子批量的一步非法时整批不改，预览不写入，同版本人机并发只成功一次。
11. 人工重置 AI 密钥后旧密钥、旧 external 会话均拒绝操作，原人工会话仍可用。检查临近到期、跨排期及撤销后的会话。
12. 协作者需有效会话才能查看；同名条目并列、来源正确、无任何令牌字段。编辑态每 20 秒心跳，隐藏/离开/退出后停止，60 秒后在线状态过期。
13. 当前浏览器工具遵守编辑权限、表单占用与草稿保护；撤销重做只操作当前页历史。负责人高亮按去除首尾空白后的姓名精确匹配，完整显式上下游依赖高亮不包含父子层级；两种高亮可共存且不改变云端版本。
14. V3 连续缩放：`Alt + 滚轮` 在 1–200 像素/天内平滑变化，鼠标日期锚点稳定；日/周/月预设恢复预设尺度，`Shift + 滚轮` 横向滚动保留。
15. V3 任务条：月视图单日短条不越到下一天，拖动及左右调整工期后日期正确；普通条/泳道条的间隙和圆角正常，汇总三角端没有原 15 px 偏移，重要节点保持日期居中。
16. PNG 按当前连续缩放、筛选和视觉间隙导出，下载文件可打开，与页面几何一致；确认没有 JavaScript 或接口异常。

数据库额度限制是业务验证的访问控制，不是网关级流量拦截。平台仍应承担请求频率/资源配额防护；全局或按排期的尝试额度可能被恶意请求耗尽。若平台无法保障 RPC 提交计数，须明确标注限流限制，将其作为测试验收版，而不能宣称公网安全验证已通过。

## 5. 源码维护与验收记录

修改 `frontend/` 后执行 `npm run build`，生成 `index.html`；上线启动无需再构建。`npm run check:sdk` 根据交付 manifest 校验 SDK；版本与官方来源记录在 `frontend/assets/workbuddy-sdk.manifest.json`，许可证位于同目录。`scripts/vendor-workbuddy-sdk.cjs --archive <官方tgz路径>` 可从验证的官方归档复现 SDK。

独立交付包可运行 `npm test` 验证随包测试；原仓库的开发阶段源码命令和范围见 [VALIDATION.md](VALIDATION.md)，发布包验收单独记录。数据库脚本见 `cloud/tests/`。本地 mock、独立 PostgreSQL 验证和真实 WorkBuddy 网关验证是不同层次，部署方应写明实际完成哪一项，不得把本地通过描述为已部署上线。

V2 专项可运行 `node cloud/tests/v2-rpc-regression.cjs`，须先按 `cloud/tests/README.md` 配置专用测试实例及 `SCHEDULE_TEST_DB=1`。脚本创建并删除自己的随机测试数据库，不要对生产库执行。当前验证记录见 [VALIDATION.md](VALIDATION.md)。

## 6. 失败恢复与部署回报

迁移前失败时保持原部署和数据库。迁移事务失败时确认回滚并报告；不要删除已成功迁移的新增表列或用 001 恢复旧函数。新应用上线失败时优先恢复上一应用版本，保留增量 schema，再用独立测试排期验证基础读写。

若必须恢复数据库快照，先暂停写入，核对升级后是否产生新数据，通过平台管理员恢复通道处理并报告恢复点与数据影响，避免覆盖有效的新修改；不自动执行清表/删库 SQL。保留失败请求与错误供修复，不能通过开放匿名写入降级权限。

部署方应返回实际网址、执行的迁移及结果、备份/恢复点标识、配置项名称（不含值）、逐项验收结果及未通过项/平台限制。`/healthz` 成功不代表数据库、编辑权限、持久化或 V3 交互通过，不能只给探活结果。
